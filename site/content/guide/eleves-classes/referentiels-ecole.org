Les illustrations, phrases proposées, libellés et compétences ajoutées sont
regroupés dans *Proposer des adaptations à l’équipe*. Les correspondances
ont leur propre bloc *Avancé* ; elles restent facultatives. Les choix et
restrictions de base décrits ci-dessous sont une démarche distincte.

* Étapes

1. Ouvrir *Gérer l’école → Référentiels de l’école*.
2. Vérifier l’*Année scolaire*, puis cliquer sur *Consulter cette année* si
   vous souhaitez en préparer une autre.
3. Dans *Choisir ou valider les propositions de l’école*, Pour commencer, garder toutes les bases autorisées par l’application et son
   choix proposé. Vous pouvez proposer une autre base sans interdire les autres.
4. Si l’équipe souhaite limiter les nouveaux choix de classe, sélectionner
   *Conserver une liste plus courte pour l’école*, ouvrir *Choisir une liste
   plus courte*, puis cocher les bases souhaitées. Le choix proposé doit
   figurer dans cette liste.
5. Cliquer sur *Voir les conséquences*, puis lire la liste et le choix
   proposé. Une explication dépliable indique les classes qui garderont une
   base hors des nouveaux choix.
6. Confirmer avec *Enregistrer ces choix pour l’année*. Le mot de passe
   est demandé pour un changement sensible ou une restriction. Au démarrage,
   le choix proposé est présenté en vert, avec le texte *Préparation initiale*.
7. *Créer une classe*, puis ouvrir *Équipe pédagogique* pour inviter les
   collègues et attribuer les fonctions.

* Résultat attendu

Les classes peuvent choisir dans la liste autorisée pour cette année. La base
proposée est un point de départ : elle n’interdit pas les autres bases de la
liste. Chaque responsable ou la direction peut ensuite
[[{{< relref "/guide/eleves-classes/choisir-referentiel" >}}][choisir la base d’une classe]]
avec son propre aperçu et sa confirmation.

*Les bases des classes déjà renseignées restent inchangées.* Leurs
observations, traces et anciens parcours sont conservés. Une restriction de
l’école ne transfère aucune réussite et n’efface aucune compétence.

Garder les autorisations proposées permet de profiter des nouvelles bases
que l’application autorisera pendant cette année. Une liste conservée par
l’école ne s’étend pas toute seule. De même, garder le choix proposé suit les
propositions de l’application ; une base proposée explicitement par l’école
reste son choix tant qu’elle demeure autorisée.

* Limites et refus

- Ne cocher aucune base dans une liste propre à l’école interdit les nouveaux
  choix de classe pour cette année. Ce choix particulier laisse les bases des
  classes existantes intactes ; l’aperçu le précise avant confirmation.
- L’école peut réduire les possibilités autorisées par l’application, mais ne
  peut pas en ajouter une interdite au niveau supérieur.
- Si une base proposée n’est plus autorisée, un message le signale. Aucun
  remplacement n’est effectué sans nouveau choix confirmé.
- Si les choix ont changé depuis l’aperçu, préparer un nouvel aperçu.
- Chaque année a ses propres choix. La nouvelle année ne recopie pas
  automatiquement les réglages de l’année précédente. Une classe close garde
  ses choix et son parcours.
- Importer de nouvelles bases reste une tâche d’administration. L’écran ne
  recherche pas de source et ne garantit pas un référentiel officiel.

Les exemples de nouvelles sources restent fictifs. La trame Petits Pas est
une trame de travail provisoire.

Pour proposer des libellés ou masquer des compétences dans l’année, ouvrir
[[{{< relref "/guide/eleves-classes/adapter-competences" >}}][Libellés et compétences masquées]].
Une classe peut adapter ces propositions ; cela ne change pas les bases autorisées.

* Changements après saisies

La liste des bases autorisées et la permission de changer après saisies sont
séparées. Ouvrir *Avancé — autoriser les changements après saisies*, puis
*Autoriser les changements après saisies*. Si l’application l’interdit pour
cette année, contacter son gestionnaire. Si elle le permet, lire l’avertissement
rouge puis *Ouvrir cette autorisation* avec votre mot de passe.

Cela ne change aucune classe : chaque classe doit aussi ouvrir son exception
et confirmer son changement, avec des avertissements et un mot de passe à
chaque opération. L’exception de classe se referme après un changement. La
permission de l’école reste ouverte jusqu’à ce que la direction la referme.
Utiliser *Refermer cette autorisation* lorsque les opérations prévues sont
terminées. Les bases actuelles et leurs prochaines saisies restent utilisables.
La nouvelle année commence avec ces permissions fermées.

*Consulter les référentiels* reste indépendant : parcourir une base, sa
provenance et sa licence n’ouvre aucune permission et ne l’adopte pas.

* Au démarrage et lorsqu’une offre manque

La préparation initiale reste simple tant qu’il n’existe aucun choix indépendant
de base de classe, adaptation, ajout, correspondance, observation ou trace.
Les nouvelles classes préparées depuis la proposition de l’école sont distinguées
des choix indépendants. Les anciennes adoptions conservent leur traitement
prudent : leur origine n’est pas déduite après coup.
Le chargement automatique de la trame ne compte pas comme une saisie.
Une classe préparée depuis la proposition de l’école conserve également sa
base : elle ne suit pas les changements futurs de l’école, même sans observation.
Les anciennes années et les traces retirées comptent aussi dans cette précaution.

Ouvrir *Pourquoi un référentiel manque-t-il ?* : vérifier l’année et une
éventuelle liste plus courte de l’école. Le défaut proposé ne limite pas la liste.

- Dans le programme ou l’application installée dans le navigateur, cliquer sur
  *Ajouter les référentiels fournis* pour l’année affichée. Cette action est utile
  pour une ancienne école qui n’a que sa trame, ou pour une nouvelle année.
  Les éditions déjà autorisées et les réglages de l’école sont conservés.
  Si l’école a choisi une liste plus courte, ajuster cette liste pour proposer
  les nouvelles sources aux classes. Les classes gardent leurs bases et leurs saisies.
- Sur un service hébergé, l’administration importe les fichiers du projet ou ses
  propres sources et les autorise pour l’année. Contacter le gestionnaire du
  service si une offre manque.

* Commencer avec des catégories seules

La proposition annuelle peut être *Démarrer sans compétences prédéfinies* :
domaines et sous-domaines sans compétences. *Partir d’un référentiel* conserve
le catalogue existant. Les nouvelles classes reprennent la proposition de
l’école ; les classes existantes ne basculent pas automatiquement.
L’ajout courant d’une réussite concerne seulement les élèves sélectionnés.
Adopter ensuite une base reste avancé et conserve ces compétences et traces.
Voir [[{{< relref "/guide/observer/ajouter-reussite" >}}][le suivi libre]].

* Échanger et composer des compétences

Dans *Référentiels de l’école → Exporter un référentiel*, choisissez une
édition à télécharger ou sélectionnez les compétences à partager. Depuis le
détail d’une compétence ajoutée, *Partager cette compétence* prépare un ZIP
avec le libellé proposé, sa section, la provenance et la licence que vous
indiquez, et éventuellement une icône fournie par le catalogue.

Pour recevoir un fichier, ouvrez *Importer un référentiel*, choisissez
*Examiner le fichier*, relisez la
provenance et les éventuels écarts, puis confirmez l’import. L’édition entre
dans le catalogue de l’école. Le suivi des classes se modifie ensuite depuis
le catalogue de compétences ou l’écran d’adoption.

Dans *Référentiels de l’école → Autorisation d’import des responsables de classe*,
la direction peut autoriser les responsables des classes actives à importer
depuis leur classe. Le réglage est désactivé par défaut et vaut pour toute
l’école. Les responsables importent dans le catalogue commun. Si l’école
restreint les choix pour l’année, la direction doit encore autoriser l’édition
avant qu’une classe puisse la choisir.

Dans *Composer une édition à partager*, vous pouvez mélanger des reprises et
des créations, ranger les créations dans plusieurs rubriques et conserver
un brouillon personnel pour l’école et l’année, accessible après reconnexion. Le téléchargement prépare l’édition
numérotée à relire avant import. Gardez le même identifiant de référentiel
pour les éditions successives et donnez un nouveau numéro à chaque révision.

* Proposer un ZIP à la direction

Depuis les réglages du référentiel de la classe, ouvrez *Proposer un
référentiel à la direction*. Examinez le ZIP, ajoutez éventuellement une
note, puis envoyez la proposition. La direction voit un compteur
*Propositions reçues* dans le bandeau et peut examiner, accepter ou refuser
la proposition. La décision figure dans *Mes propositions* pour la classe.
Si l’école conserve une liste annuelle restrictive, l’édition doit encore
être autorisée pour l’année. Chaque classe choisit ensuite si elle l’adopte.

La proposition est visible aux comptes de la même installation. Si les
postes utilisent des installations séparées, transmettez le ZIP comme
fichier. Voir [[{{< relref "/referentiels/partage-entre-ecoles" >}}][partager des référentiels entre écoles]].

* Découvrir et suivre des référentiels

Dans *Référentiels de l’école*, ouvrez *Découvrir des référentiels*.
Les référentiels embarqués et le catalogue Grist de démonstration y
figurent. Ouvrez *Détails* pour retrouver les éditions et le lien du
catalogue. *Ajouter un catalogue par lien* examine un document public de
=grist.numerique.gouv.fr= contenant les tables =Editions= et =Competences=
du pilote. Le lien reste disponible dans le répertoire de l’école.

*Suivre* mémorise votre choix pour l’école. *Vérifier les éditions* relit
les catalogues suivis. Examinez l’édition avant de confirmer l’import.
Chaque classe choisit ensuite si elle adopte l’édition. *Ne plus suivre*
retire le suivi et laisse les éditions reçues dans le catalogue de l’école.
La lecture Grist de ce pilote s’effectue depuis le serveur Petits Pas.

* Partager le référentiel courant d’une classe

Dans les réglages du référentiel d’une classe active, ouvrez *Exporter un
référentiel*, puis *Partager le référentiel de cette classe*. Renseignez le
titre, le numéro d’édition, la provenance, les crédits et la licence.
Gardez le même identifiant pour les révisions de votre référentiel.

Examinez les compétences communes visibles, leurs libellés, leurs
formulations et leurs illustrations avant de télécharger le ZIP. Relisez
les textes libres pour écarter toute mention individuelle. Les observations,
les suivis ciblés et les photos ne sont pas exportés. Pour transmettre la
base telle qu’elle a été publiée, utilisez *Exporter l’édition d’origine*.

* Publier le référentiel d’une classe dans Grist

Dans l’aperçu du référentiel à partager, choisissez *Publier dans Grist*.
La dernière destination où vous avez publié pour cette école est proposée.
Pour en choisir une autre, ouvrez *Choisir une autre destination*. Dans un
document préalablement préparé, Petits Pas peut publier un nouveau
référentiel ou ajouter une édition. Avant de confirmer, vérifiez le nom
du document, le référentiel et le numéro proposés.

Le document Grist de ce pilote doit contenir une table =Editions= avec
=Numero= (entier), =Referentiel=, =Titre= et =Contenu= (texte). Petits Pas
écrit une édition complète dans une ligne et vérifie sa présence. Le
document doit autoriser l’écriture pour la connexion utilisée. Réservez
les essais avec un document ouvert en écriture à des contenus fictifs.
